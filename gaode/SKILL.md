# 周边去哪儿：基于高德的地点推荐

## 用途与适用场景

用户用一句话描述「我在哪 + 想要什么 + 有什么限制」，需要你给出附近值得去的地点，并说明怎么走过去。

典型输入：「我在杭州某地铁站，想找一家咖啡馆，步行不超过 15 分钟，推荐最多 3 家，优先近一点的。」

输入约定：评测会提供城市和明确的起点坐标，不需要实现设备定位。若用户只给了地点名而没给坐标，先用地理编码解析；仍解析不出就如实说明，不要猜坐标。

## 执行流程

平台提供的高德 MCP 工具名可能与本文示例（`maps_around_search`、`maps_direction_walking` 等）不同。每次调用前先按能力对齐一次：周边/关键词搜索、步行路径规划、地理编码、POI 详情、距离测量、逆地理编码。只要平台提供了对应能力的工具就直接用它，不因名称不一致而跳过该步骤。

### 1. 解析需求

从用户原话中抽出 5 项，缺哪项用默认值并在回答中说明：

| 要素 | 说明 | 缺失时 |
| --- | --- | --- |
| 城市 | 用于校验搜索结果是否在同一城市 | 用起点坐标反查 |
| 起点坐标 | 「经度,纬度」，高德 GCJ-02 坐标系 | 先用地理编码工具解析地名 |
| 地点类型 | 咖啡馆 / 餐厅 / 公园等技术词 | 需求不明确时先追问一次 |
| 步行时间上限 | 分钟 | 默认 15 分钟 |
| 推荐数量 | 用户要几个 | 默认 3 个，硬上限 3 个 |

排序偏好单独记一下：用户说「优先近一点」就按步行距离升序；没说也按步行距离升序。

### 2. 搜索候选地点

调用周边搜索工具：

- `location`：起点坐标，格式 `经度,纬度`，保留 6 位小数
- `keywords`：用户的地点类型词
- `radius`：从 1500 米起步
- 需要地址、POI 类型、精确坐标时，用详情搜索按 POI id 补齐
- 起点本身不确定行政区时，用逆地理编码反查城市

初筛规则：

- 只保留类型与需求一致的地点。搜「咖啡馆」返回咖啡豆商店、咖啡器具店要剔除
- 同一家店有多个分店时按 POI id 去重，只留离起点最近的那家
- 候选少于 3 个时，把 `radius` 扩大到 3000 米再搜一次，不要直接放弃

### 3. 逐条查询步行路线

对每个候选调用步行路径规划工具：`origin` = 起点坐标，`destination` = 该 POI 坐标。

硬性要求：

- 步行距离和步行时间**只能**取步行路径规划返回的 `distance` / `duration`
- **不得**用距离测量工具的直线距离替代，也不得按坐标手算
- 耗时超过用户上限的地点直接排除，即使它很近
- 单条路线查询失败时，该地点标注「路线未获取」，不进入推荐列表

### 4. 筛选与排序

1. 先按步行时间上限过滤
2. 按步行距离升序排序
3. 取前 3 个
4. 表格里的距离、时间、顺序必须与路线查询结果逐条对上，不能手工润色数值

### 5. 生成回答

推荐命中时：

> 从「XX 地铁站 B 口」出发，步行 15 分钟内可以到这几家：
>
> | # | 地点 | 地址 | 步行距离 | 步行时间 | 推荐理由 |
> | --- | --- | --- | --- | --- | --- |
> | 1 | XX咖啡（XX店） | XX区XX路XX号 | 420 米 | 约 6 分钟 | 距起点最近，位于 XX 商场一层 |
> | 2 | YY咖啡（XX店） | XX区XX路XX号 | 780 米 | 约 11 分钟 | 沿 XX 路直行可达，在 XX 写字楼底商 |
> | 3 | ZZ咖啡 | XX区XX路XX号 | 960 米 | 约 14 分钟 | 三家中步行时间最接近上限，靠近 XX 公园东门 |
>
> 以上距离与时间来自高德步行路径规划。营业状态、排队情况和环境安静程度未核实。

要求：

- 每个地点必须齐五项：名称、地址、步行距离、步行时间、一句推荐理由
- 推荐理由只写有数据支撑的内容：距离、方向、所在商圈、POI 类型。「环境安静」「不用排队」「味道好」「性价比高」这类无法从查询结果得到的信息不写；用户主动问起时答「未核实」
- 开头一句话交代起点的处理方式（用户给的坐标，还是解析出来的地址）
- 结尾统一注明数据来源，以及哪些信息未核实
- 保持简洁，不复述工具原始 JSON

## 特殊情况处理

| 情况 | 处理方式 |
| --- | --- |
| 符合条件的地点不足 3 个 | 有几个推荐几个，说明「步行 X 分钟内只找到 N 个符合条件的地点」，并给出可放宽的方向（时间、半径、关键词） |
| 一个都没找到 | 如实说明范围内没有符合条件的地点，提 1–2 个放宽建议，不编造地点 |
| 起点坐标缺失且地名解析失败 | 说明无法定位起点，请用户补充坐标或更完整的地址，不猜坐标 |
| 部分步行路线查询失败 | 失败的地点标「路线未获取」且不列入推荐；在回答末尾说明有 N 个地点因路线查询失败未纳入 |
| 全部路线查询失败 / 工具报错超时 | 如实说明是高德服务调用失败，不返回任何未经验证的地点；可重试一次，仍失败则建议稍后重试 |
| 用户要超过 3 个 | 按 3 个给，说明本题上限为 3 个 |
| 用户跨城市提问 | 以起点坐标所在城市为准，搜索到其他城市的结果剔除 |

## 禁止事项

- 不编造地点名称、地址、坐标、距离、步行时间
- 不用直线距离、驾车时间、骑行时间代替步行路线
- 不把超出步行时间上限的地点写进推荐表
- 不把未核实的信息（营业状态、排队、评分、人均）写成确定结论
- 不在 Skill 正文或回答中输出任何 API Key、token 或密钥
